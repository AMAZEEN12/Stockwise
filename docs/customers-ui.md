Both features use the same form, generated CustomerCreate/Customer types and resource API. Real data is never replaced with fixture names or balances. Duplicated names are allowed by the current contract; identity is the UUID. Display fictional contact text when needed to distinguish equal names. A successful create updates the shared customer cache and selects the returned UUID in the picker. Do not send a sale on customer creation. Pending sales keep their immutable snapshot and cannot open/change the picker.

The current contract supports list/search/create. Use complete paginated collection loading for this small demonstration and filter names locally only after all pages succeed; preserve server order. Never show a partial list as the complete directory or an empty successful list after an error. Display timestamp means last successful client retrieval in Africa/Lagos, not server computation. Keep the last successful time while refreshing and disclose refresh failures. Proposed server search/order/snapshot behavior is separate.

Create is non-idempotent. Disable duplicate taps; never automatically retry POST. Definitive validation/auth failures keep values and permit correction. Transport/5xx/unreadable-success outcomes preserve an unresolved, user/service-bound attempt in tab storage and offer checking the list, not another create. Keep the form and explain uncertainty; do not assert Nothing was added for these outcomes. Returning to a form or refreshing must not forget that attempt. List matches are candidates for explicit user selection, not proof based on a non-unique name. Clearing an unresolved attempt requires explicit acknowledgement after checking. Storage failure blocks sending rather than promising recovery. Creating customers does not activate the pending real store-credit settlement proposal.

Missing picker saving/save-error/no-search-match frames reuse the Customers form/state styling. Decorative icons use SVG. Existing Sales tests will change only their selection interactions from the replaced native select to the picker; retain the money, role and no-write assertions. This is a feature change, not a bug-fix test exception.

Verification, capture coverage, measured differences and limitations will be appended after the checks run. Reference images remain ignored inputs; runtime images belong in assets/images with central exports. No new artwork is required for these screens.
