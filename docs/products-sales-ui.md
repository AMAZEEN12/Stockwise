## Implemented behavior and verification, 2026-10-25

- Products commit: 86fb5ea. Sales is stacked on that branch. The existing /workspace sign-in handoff now links to the shop; safe returnTo navigation restores checkout after explicit sign-in. Shared primitives retain their source ownership. Resource APIs inject endpoints into the existing single RTK cache.
- Form categories use an editable datalist populated from all catalogue pages because v0.1.0 permits a free-text category. This preserves category entry without inventing /categories. Native category arrows can vary by browser. Product writes are never automatically retried.
- Cart quantity controls follow the updated bordered-field references across all states. Stock conflict re-fetches products instead of parsing error prose, corrects quantities, keeps zero rows visible and blocks confirmation until removal. Real service conflict response and price-guard improvements remain proposals.
- Sale writes persist their snapshot first, lock editing, use the same key/body across the bounded transport retry and refresh/reauthentication, and recheck the author/role. A 409 returns to an editable cart with a new key on the next explicit confirmation. 422 does not silently generate another submission. Local Discard does not erase an unresolved write or reverse a sale; resolution is required before starting another. Cart drafts persist per user; pending snapshots also bind the service URL.
- Store credit: corrected 6000 applied / 150 due example works in the explicitly labelled simulation. Real credit-bearing submissions stay blocked until the API supplies authoritative settlement fields. Current displayed preflight prices cannot prevent the remaining server price race; receipt lines use returned server prices. Customer selection remains visible if switching a selected credit customer to Paid, allowing the existing optional customerId semantics without hidden selection.
- Development simulation runs only on loopback, resets on restart and supports configured OWNER/ASSISTANT/ADMIN fixtures. All login inputs are examples, not credentials. It validates the used request shapes, preserves idempotent responses in memory and exposes only existing contract paths used by the UI. It is neither database business-rule enforcement nor deployed concurrency evidence. Original Prism mode remains available separately.
- Sales history, edit/archive and proposed endpoints remain deferred. View in Sales is disabled with an explanation. Design-only Pending decision annotations are omitted from the product; simulation labels/logout access remain visible. One responsive tablet column avoids squeezed carts between phone and desktop widths.

Checks passed: lint, strict typecheck, 5 unit files / 10 tests, production build, unchanged-contract lint, 30 Playwright cases in 3.1 minutes, and actual un-intercepted local API/browser journeys. Browser cases include both supplied desktop/mobile sizes, axe, role changes, price acceptance, 10,000-unit limit, 320/360/768/1024/1440 bounds, 401 reauthentication and immutable retry/reload recovery. Service verify could not run because JAVA_HOME is not correctly configured. Production build reports a 526.17 kB main chunk (173.16 kB gzip); this is recorded rather than suppressing the warning.

Quality artifacts stay local in web/test-results and web/.mock/design-comparison.json. Latest comparison: stock conflict desktop 3.23% / mobile 8.74%; corrected credit desktop 6.85% / mobile 19.21%. Credit includes the deliberately omitted design annotation and added simulation label. ## Default sale catalogue, 2026-10-26 (DM63-DM64)

Victor authorized showing products before typing. Implemented on feat/sale-product-catalog from latest merged main 6bf48b8; technical choices/logged by Codex. The new feature-specific SaleProductCatalogue composes existing shared primitives, with a bounded scrolling list and explicit Products/Alphabetical by name labels. Initial loading, empty catalogue, no matches, read errors and prefix retry have separate states. Existing cart, stock/price preflight, customer selection and immutable uncertain-sale recovery remain unchanged.

Requests use the existing q/page/size contract only. Pages contain 20 source rows; archived-only pages are traversed until a visible batch or the end. Out-of-stock active products remain visible but disabled. Each displayed prefix is sorted by lowercased name/UUID. Load more and refresh re-read the prefix, rejecting inconsistent/unsafe responses rather than combining stale and current pages. Previously loaded rows remain visible but unavailable after failure; different searches never show previous-query results. The current service already orders products before pagination; an explicit contract guarantee/Unicode semantics remain proposed in products-sales-contract-proposal.md, without claiming API-owner approval.

The default catalogue intentionally occupies the formerly empty search-results area. The list is height-bounded on mobile so the cart remains reachable. No new reference-perfect comparison is claimed. See sales-usability-plan.md for the approved remaining sequence and WORKLOG for actual validation, environmental limits and publication.
